Preview links for mockups

Every time you push your own branch, your mockup gets a link of its own. Nobody has to deploy anything. This page tells you how to name your branch, how to work on it, and where to find the link.

What you get

  • A link for every push. A few minutes after you push, your work is live at a link only your branch has.
  • A “latest” link that follows you. Send it once; every push you make updates it.
  • A fixed link for every commit. Good for “look at this exact version”. The last five commits of each branch are kept; older ones are removed.
  • The dev link stays clean. Nothing changes on the normal dev link until your work is approved and landed.

One rule: your branch name starts with dev/

The link only appears for branches whose name begins with dev/. After the slash, say which mockup and what changes. Short, lowercase, words joined with dashes.

GoodNot good
dev/buyer-app-cod-checkoutrahul — nobody can tell what is in it
dev/seller-store-kyc-empty-statedev-cart — no slash, so no link
dev/analytics-reports-filterstest2, new-branch, wip

Never push straight to dev, testing, staging or main.

Those branches are the shared environments. dev is the shared dev demo. testing, staging and main go to other environments that the engineering team owns.

The small badge in the corner of every screen names the build you are looking at, for example dev-seller-store-kyc-empty-state-3f9c2a1. If it says something else, you are on a different build.

Day to day

If you work with Claude Code

You do not need to type git commands. Say what you mean and it does the rest, on the right kind of branch:

  • “I’m starting on the KYC empty state in the seller store” — makes a fresh dev/… branch from today’s dev.
  • “Save my work” — commits and pushes. Your link updates a few minutes later.
  • “Pull the latest” — brings in what others have landed on dev.
  • “Send me a link” — gives you the preview link to share.
  • “It’s approved, put it on dev” — lands it on the shared dev demo.

If you use git yourself

  1. Start from fresh dev, on a new branch. 
    git switch dev
git pull
git switch -c dev/seller-store-kyc-empty-state
git push -u origin HEAD
  2. Work, then save and push. Small saves, each with a plain message that says what changed. 
    git add -A
git commit -m "Seller store: empty state for the KYC list"
git push
    A few minutes later your link is updated.
  3. Share. Open the branch list above, click your branch, copy the latest link. If the screen you want to show has a # in its address, copy the whole address including that part — it says which screen opens.
  4. Stay up to date. When others land work on dev, bring it into your branch: 
    git fetch origin
git merge origin/dev
git push
  5. When it is approved, ask for it to be landed on dev. The normal dev link then updates for everyone.

Good to know

You seeWhat it means
Your branch is not in the list yetThe build takes a few minutes after the push. Refresh. If it is still missing after ten minutes, check the branch name starts with dev/.
“No such build”That commit was never built, or it is older than the last five on that branch. Use latest or a newer commit.
A picture is missing on your screenImage paths in the app must start with ./, not /. Tell Claude Code “the picture on X is broken” and it will fix the path.
Addresses have a # in them, like /#/ordersNormal. That is how the mockups keep track of which screen is open. Share the whole address.
The badge in the corner shows a different buildYou opened a different link. Go back to the branch list and pick yours.
Something on the shared dev link brokeNothing you push to a dev/… branch can change the shared dev link. Someone landed a change; tell the team.

In one line

Branch from dev, name it dev/<mockup>-<what>, push often, share the latest link, ask to land it when it is approved.
